# AI 思考与写作

维护用户的个人思考与内容生产管线，不虚构用户的经历、观点或公开立场。

在模板仓库内改变成熟度或内容状态时，读取项目根目录的 `WORKFLOW.md`；规划、起草、审核或准备公开内容时，读取 `WRITING_GUIDE.md`。若独立安装 Skill 的工作区不存在这些文件，不得因此阻塞任务；以下规则是可独立执行的完整默认流程。

## 核心边界

- 用户是自身经历、感受、观点、立场和公开表达意图的唯一来源。
- Agent 补充必须标记为建议、解释、推测、综合判断或待核实事实。
- 外部来源和正式 Wiki 由 `ai-learning-llm-wiki` 管理；本 Skill 不写入 `raw/`、`staging/`、`reviews/` 或 `wiki/`。
- 表达完整不等于观点成熟。状态升级必须取得下文规定的用户授权。
- 未经用户另行明确指定平台和最终版本，不执行外部发布。创建 `content/ready/` 只表示版本已准备好，不构成发布授权。

## 工作目录

只在首次产生实际内容时创建相应目录：

```text
inbox/thoughts/INBOX.md   追加式个人素材收集箱
inbox/conversations/      经选择保存的澄清对话
notes/developing/         经确认值得发展的单一想法
notes/established/        用户确认的稳定观点
topics/                   连接 Wiki、观点和内容的导航
content/seeds/            用户确认的内容机会
content/series/           用户确认的系列规划
content/drafts/           可编辑文章草稿
content/ready/            已确认准备发布的最终版本
content/published/        不可静默覆盖的发布快照和地址
```

`wiki/` 回答“经审核的外部资料说明什么”；`notes/established/` 记录“用户经过反思后目前怎么想”。内容可以同时引用两者，但两者不能互相替代。

## 信息角色

在歧义会影响判断时，明确区分：

- **外部事实（External fact）**：来自正式 Wiki 的可核实主张，或仍需摄取、核验的外部信息。
- **用户经历（User experience）**：用户陈述亲自发生过的事情。
- **用户感受（User feeling）**：用户的情绪或主观反应。
- **当前解释（Current interpretation）**：用户目前的解释，未来可能变化。
- **推测假设（Hypothesis）**：尚未确认的可能性，并注明来自用户还是 Agent。
- **稳定观点（Stable viewpoint）**：用户经过澄清后明确确认的立场。
- **公开主张（Public claim）**：用户已批准面向外部受众使用的表达。
- **Agent 建议（Agent suggestion）**：可选的框架或建议，默认不代表用户观点。

## 模式选择

选择满足请求所需的最低成熟度：

```text
捕获 Capture → 澄清 Clarify → 发展 Develop → 确立 Establish
→ 内容种子 Seed → 规划 Plan → 草稿 Draft → 发布准备 Prepare → 发布归档 Archive
```

即使素材已经很多，也不得擅自跳级。用户可以明确授权进入后续模式，但真实性、隐私、事实核验和外部发布边界始终有效。

### 捕获 Capture

用于用户只要求记录想法、经历、感受、问题或一句话的情况。

1. 追加到 `inbox/thoughts/INBOX.md`；仅在第一条真实素材出现时创建文件。
2. 保留用户语言。可以轻微整理标点，但不能把想法润色成结论。
3. 添加当前日期和简短标题；Agent 补充必须显式标注。
4. 不创建独立笔记、内容种子或文章。

### 澄清 Clarify

用于用户希望讨论一条重要或含糊的想法。

1. 确定当前只讨论一个核心想法。
2. 一次只问一个最影响判断的问题，例如背景、案例、感受、结果、矛盾或边界。
3. 复述当前理解，但不宣布观点已经稳定。
4. 仅在用户要求保存，或升级时若不保存会丢失关键推理的情况下，写入对话记录。

仅完成澄清，不授权创建 `notes/developing/` 文件。

### 发展 Develop

仅当用户同时确认以下两点时，才创建候选笔记：

- 该想法值得单独发展；
- Agent 当前表述没有歪曲用户原意。

读取 `references/candidate-note-template.md`，在 `notes/developing/` 中为每个可独立讨论的想法创建一个 Markdown 文件。链接相关 INBOX 条目或对话记录，不复制无关素材。

候选笔记必须保留不确定性、反例、适用边界和待确认事项。除非确属同一想法，不要把工具选择、方法、个人感受和普遍结论合并。

### 确立 Establish

只有用户明确确认观点已稳定到可复用程度时，才把发展中笔记移动到 `notes/established/`。

移动前：

1. 用一到两句话陈述观点。
2. 指出剩余假设或未解决事实。
3. 若当前指令未包含确认，向用户确认。

确认后保留既有推理和观点变化，将元数据改为 `Status: Established` 并记录确认日期。不得删除能解释观点演变的旧结论。

### 内容种子 Seed

用于用户希望探索哪些内容值得公开写作的情况。

1. 搜索 `notes/established/` 中相关的用户观点。
2. 搜索 `wiki/index.md` 和 `wiki/` 中经审核的外部知识及反方信息。
3. 经用户允许，发展中笔记可以提供问题或案例，但不能冒充稳定立场。
4. 先在对话中提出一个或多个种子摘要；不能仅因素材充足就自动建文件。
5. 用户确认后，读取 `references/content-seed-template.md`，创建 `content/seeds/<slug>.md`。

每个种子必须分开记录：用户论点、个人经历、外部支持、反方观点、缺失材料、目标读者和预期形式。

### 规划 Plan

只有用户确认内容种子并要求系列，或用户接受“需要拆成多篇”的建议后，才创建系列规划。

每篇文章只解决一个主要读者问题，按读者理解顺序组织，而不是按来源时间排列。已确认计划保存到 `content/series/`。

### 草稿 Draft

仅从用户确认的内容种子或系列条目生成完整草稿。若项目根目录存在 `WRITING_GUIDE.md`，先读取它。

- 保留用户语言、犹豫、观点变化和实践边界。
- 起草时使用标准 Markdown 相对链接连接内部知识和笔记。
- 对时效性或证据不足的事实标记 `[待核实]`。
- 不虚构场景、对话、结果、数据、引语或情绪反应。
- 保存到 `content/drafts/`，不覆盖已发布快照。

### 发布准备 Prepare

只有用户明确确认指定修订版是最终发布版本时，才能把草稿转入 `content/ready/`。

1. 读取 `references/publication-ready-template.md` 和 `references/publication-review-checklist.md`。
2. 检查时效事实、来源归属、隐私、版权、标题与正文一致性，以及事实与个人观察的区分。
3. 清除所有 `[待核实]`、`TODO` 和 `TBD`；否则返回草稿阶段。
4. 新建 Ready 文件，不静默替换原草稿。
5. 使用当前环境可用的 Python 3 启动命令（`python3`、`py -3` 或 `python`）运行：

   ```text
   <python3-command> <skill-dir>/scripts/check_publication.py <project-root> content/ready/<file>.md
   ```

6. 分开报告机械检查结果和人工判断清单。

机械检查通过只表示文件在形式上准备完成，不授权外部发布。

### 发布归档 Archive Publication

仅在用户说明内容已经发布，或明确授权通过可用平台工具发布后使用。

- 任何外部操作前，再次确认准确的 Ready 版本和平台。
- 将最终公开文本保存为 `content/published/` 中新的不可变快照。
- 记录发布日期、平台、公开 URL 或平台标识，以及来源 Ready 文件。
- 没有 URL 时如实说明，不得编造。
- 后续修订应创建新版本或明确的更正记录，不静默改写历史发布。
- 不把用户自己的已发布文章重新摄取为独立外部证据；第三方回应或新外部来源可以正常摄取。

## 主题地图与跨管线使用

`topics/` 可以链接相关 Wiki 页面、稳定观点、开放问题、内容种子、草稿和已发布内容。主题地图保持简洁，只做导航，不复制正文。

写作所需的外部事实若不在正式 Wiki 中：

- 草稿阶段标记为 `[待核实]`；或
- 请求先使用 `ai-learning-llm-wiki` 完成 Research/Ingest。

不得把修改正式 Wiki 当作写作的附带动作。

## 完成报告

每次写入任务都报告：

- 使用的模式和达到的成熟度状态；
- 新增、修改、移动和删除的文件；
- 本次依赖的用户确认；
- 尚未解决的事实、隐私风险或发布阻碍；
- 发布门禁是否运行并通过；
- 下一步允许进入的状态。
